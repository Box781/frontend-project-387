# API contract (TypeSpec)

Единый источник правды для фронтенда и бэкенда. Сначала меняем этот контракт, потом обе части приложения.

## Домен

| Сущность | Что это | Где в API |
| --- | --- | --- |
| Owner | Один заранее заданный владелец календаря. Аккаунтов нет. | `GET /admin/owner` |
| EventType | Тип встречи: `id`, `title`, `description`, `durationMinutes` | `GET/POST …/event-types` |
| Slot | Свободный интервал `[startAt, endAt)` на 14 дней вперёд | `GET /public/event-types/{id}/slots` |
| Booking | Запись гостя на слот | `POST /public/bookings`, `GET /admin/bookings` |

Гость идёт по `/public/*`, владелец — по `/admin/*`. Авторизации нет: граница ролей только в URL.

## Сценарии

**Гость**

1. Смотрит виды брони: название, описание, длительность.
2. Выбирает тип события и видит свободные слоты на ближайшие 14 дней.
3. Бронирует слот: имя, email, `startAt`.

**Владелец**

1. Создаёт тип события (`id` задаёт сам).
2. Смотрит один список предстоящих встреч по всем типам.

## Правила

- Окно записи: 14 календарных дней от текущей UTC-даты.
- Слоты: пн–пт, 09:00–18:00 UTC, шаг равен длительности типа.
- Занятость: два бронирования не могут пересекаться по времени, даже у разных типов событий.
- В прошлом слоты не предлагаются и не бронируются.
